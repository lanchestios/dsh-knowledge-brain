Structured writing，技术写作行业用来提升信息质量的一套通行做法：**不把文档当成连续的散文，而是拆成有明确类型、能被单独阅读的单元**。

这一脉的源头是 Horn 的 [[信息映射]]（1967），它还吸收了 Hughes 飞机公司的 STOP 方法。后来的框架都建在它的类型学上。

## 传承

```
1967  信息映射（Horn）            块 · 标签 · 七种信息类型
   │
   ├─ 1980s 极简主义（Carroll）    读者的目标从来不是读文档
   │
   ├─ 2001  DITA（OASIS）          把类型学做成 XML 架构：概念 / 任务 / 参考
   │     │
   │     └─ 2013 EPPO（Baker）     每一页都可能是读者的第一页
   │
   └─ 2017  Diátaxis（Procida）    两轴四象限，一页只服务一种用途
```

另有一条独立发展的支线：Matuschak 的 [[常青笔记]]（源自 Luhmann 的 Zettelkasten），它关心的不是文档而是**个人知识的积累**，但在「按概念切分」这一点上和上面这一脉完全同调。

## 分工

四套方法管的是不同层级，不冲突：

| 层级 | 谁管 | 它回答的问题 |
|---|---|---|
| 一页**之内** | [[信息映射]] | 怎么分块？这块信息该长成表、树还是编号列表？ |
| 一页**是什么** | [[Diataxis文档框架]] | 这页服务哪一种读者需求？参考和解释混了没有？ |
| 页**与页之间** | [[常青笔记]] | 按概念还是按来源切？链接够不够密？ |
| 写**多少** | [[极简主义]] | 什么该留在页内、什么该链接出去？ |

## 没单开页的两套

DITA 和 EPPO 的要点记在这里。

**DITA**（Darwin Information Typing Architecture，OASIS）把 Horn 的类型学固化成可校验的 XML 架构。基础类型是 **Concept**（概念，是什么）、**Task**（任务，怎么做）、**Reference**（参考，有哪些事实），另有 glossary entry（术语条目）等。它的贡献是让「类型」可被工具强制，而不只是写作纪律——DTD 或 Schema 会引导作者按该类型的结构写。topic（主题）存成独立文件，用 map（图）组装成手册或帮助系统。

**EPPO**（Every Page is Page One，Mark Baker 2013）的前提是：网上任何一页都可能是读者看到的第一页，所以每一页必须**能被单独用**——不只是能被单独读。七条原则里对本仓库最有用的三条：

| 原则 | 内容 |
|---|---|
| **Self-contained**（自足） | 不假设读者读过任何相关页，但可以假设他懂这个领域。没有上一页下一页，没有父页子页 |
| **Conform to type**（符合类型） | 类型不是「概念 / 任务 / 参考」这种通用词，而是**由主题本身决定**——同一类主题天然包含同类信息，且顺序相同 |
| **Stay on one level**（停在一个层级） | 主题被随机访问，所以换层级的决定权在读者，不在作者 |

「符合类型」是本仓库骨架规则的直接来源：写规范就用规范的骨架，写方法就用方法的骨架，同类才可横向对比。
