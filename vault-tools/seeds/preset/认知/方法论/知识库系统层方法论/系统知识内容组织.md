系统知识内容组织，用来让不同读者找到完成任务所需的知识。先识别读者带来的问题，再确定入口、正文维护处和下钻路径；内容类型辅助选择表达方式，不能直接替代业务或工程层级。

## 问题起点

同一系统涉及业务、使用、研发与运维等问题。把所有事实按技术属性堆放，会使使用者找不到操作路径；按每种读者复制一套正文，又会使共同规则逐渐分歧。

内容组织解决阅读与维护问题，[[系统知识建设推进]] 解决目标到交付的依赖问题。两者分别验收，不以目录是否齐全判断建设成熟度。

## 核心构件

### 读者问题

| 读者问题 | 入口内容 | 后续下钻 |
|---|---|---|
| 为什么值得做 | 业务结果、痛点与衡量方式 | 价值依据、目标与取舍 |
| 这一摊是什么 | 定位、范围、全景与关键术语 | 子域、能力、系统或构件 |
| 怎样办成一件事 | 角色目标、前置、动作与反馈 | 任务指南、规则及例外 |
| 系统怎样工作 | 构成、边界、关键行为与质量约束 | 架构与实现证据 |
| 怎样部署和处理问题 | 环境、发布、恢复及故障入口 | 部署说明、排障与经验 |
| 接下来改变什么 | 差距、方案、依赖与验收 | 规划、项目、故事和决策 |
| 找谁确认 | 业务、技术、运行与知识维护责任 | 对应责任范围与交接方式 |

这些是阅读入口，不是每个对象必须建立的固定同级目录。只服务少量问题时，一份有清晰分节的文档即可。

### 渐进展开

| 层次 | 保留内容 | 下钻触发 |
|---|---|---|
| 入口摘要 | 对象定位、范围、关键术语、按问题导航 | 读者选定目标或关切 |
| 主题正文 | 一个稳定问题的事实、步骤或解释 | 某个分支有独立任务和维护需要 |
| 条件细节 | 特殊场景、环境差异、完整契约、专项例外 | 触发条件已满足，明确说明何时需要 |

入口直接标明主要分支及适用条件，避免连续穿过多页才知道有没有所需内容。长页先提供目录或检索词；长度本身不产生新的主题边界。

### 内容分工

| 内容类型 | 主要回答 | 组织方式 |
|---|---|---|
| 参考事实 | 有什么、定义是什么、参数有哪些 | 概念、字段、状态、契约与证据 |
| 任务指南 | 怎样完成一次具体任务 | 前置、步骤、反馈、检查与恢复 |
| 解释与决策 | 为什么这样设计、有哪些取舍 | 问题、约束、候选、决定与后果 |
| 学习引导 | 首次理解需要经过什么 | 必要概念与循序场景，引用正式规则 |

这是按阅读目的归纳的表达选择，不要求四类各立目录。可执行脚本、部署配置和模板属于产物或工具，知识说明记录它们的用途与使用条件，不把产物文件当成规则正文。

### 唯一维护处

业务规则、接口契约和实现机制分别确定主要维护处，其他入口引用。一个对象有多种视角并不等于重复：功能描述可观察行为，架构解释边界与机制选择，实现记录具体执行和证据。

横切内容放在覆盖范围最近的共同层，并明确责任。共同权限或审计规则不归入某一个业务分支，各分支只记录自身特例。

通用动作的条件与影响只维护一次；流程记录情境特例，操作指南记录实际动作。经验依附它解释的任务或故障；出现独立、稳定的检索问题时可以另立专题。

### 拆页与合页

| 判断 | 拆页条件 | 先留同页的情形 |
|---|---|---|
| 独立问题 | 有稳定读者任务，可清楚命名 | 仅是上一段的解释或证据 |
| 边界与依据 | 范围清楚，有足够材料支撑 | 只有标题和猜测 |
| 维护责任 | 能独立更新，不必同步改写大量邻页 | 高度同变、拆后反复跳读 |
| 验收能力 | 能单独判断内容是否回答问题 | 必须依靠多个碎片才成立 |

跨页关系多时先检查是否切错维度。只有内容多，可以分节和加导航；只有一两句，不为目录对称建立空页。

## 操作规则

1. 按 [[知识库系统层分层方法]] 明确对象范围，列出主要读者任务和成功条件。
2. 选定主要组织维度，建立问题到内容的导航；其他维度用索引、标签或引用表达。
3. 为共同规则确定维护处，分开现状与目标、操作任务与内部解释。
4. 业务操作只写完成任务所需信息；对接任务实际需要的接口可以出现，不能用“含接口”一律判越界。
5. 治理描述资产的提议、评审和废止，使用描述角色怎样办事；同一人可以承担多种责任。
6. 按拆页判据生长主题，按实际阅读问题合并碎页；成员内部切分用 [[系统层成员拆解方法]]。
7. 规则变更时沿引用检查受影响指南，明确哪些仍适用、哪些需要重验。

### 内容记录

| 项 | 需要说明 |
|---|---|
| 读者与任务 | 谁带着什么问题来，怎样判断成功 |
| 内容职责 | 参考、任务、解释或学习引导，主要解决哪一项 |
| 维护与引用 | 哪些定义在此维护，哪些直接引用 |
| 事实状态 | 当前、目标或推测，证据及适用条件 |
| 下钻条件 | 什么情况下需要读哪个分支 |

### 验收判据

- 读者能从入口找到正确主题，无需先了解内部目录或源码。
- 操作指南无需无关技术背景即可执行；对接与研发所需技术细节也有明确位置。
- 同一规则没有在角色、流程、功能和实现里平行维护。
- 目标与现状可区分；“没有”用于说明真实能力边界，未知不写成不存在。
- 每个独立页面有真实问题和内容，薄页、循环跳转及过深导航得到处理。

## 可信边界

入口与渐进披露来自技能组织方式的类比，内容类型是结合系统知识任务作的归纳；它们不是必须照搬的目录模板。

不同读者可能需要不同深度，同一任务也可能横跨业务和技术。应以完成任务所需的信息判断边界，而非按角色身份或技术标识机械隔离内容。
