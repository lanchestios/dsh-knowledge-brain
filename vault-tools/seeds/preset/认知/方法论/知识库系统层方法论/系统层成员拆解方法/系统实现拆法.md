系统实现拆法，用来解释当前行为具体怎样被工程机制执行。围绕技术触发、执行路径、状态变化、输出和失败恢复展开，结论能回到代码、配置、数据定义或运行记录。未实现的技术方案明确标为目标设计，不能混入现状实现。

## 问题起点

实现知识若重复页面按钮和用户操作，会与功能说明重叠；若只有文件、接口和表清单，又无法说明行为。有效拆解需要把技术入口、关键机制和可观察结果连成路径。

## 核心构件

### 选择主轴

| 分解主轴 | 适用问题 | 避免的混淆 |
|---|---|---|
| 用例或运行路径 | 一次请求、事件或批次怎样完成 | 不按前后端文件夹切断完整行为 |
| 组件或公共机制 | 一个稳定构件、算法或共享机制怎样工作 | 不在每条路径复制公共逻辑 |
| 数据生命周期 | 数据怎样产生、加工、存储、消费和清理 | 不把物理库边界等同业务责任 |

同一层选择一个主要分解维度，其他维度通过引用和索引关联。功能族可以提供入口，但不要求实现页与功能页数量或名称相同。

### 路径记录

| 环节 | 需要说明 |
|---|---|
| 技术触发 | 请求、消息、定时任务或状态变化从哪里进入 |
| 输入与校验 | 输入结构、前置状态、授权与校验责任 |
| 关键执行 | 跨哪些构件，谁调用或发布什么，依赖怎样满足 |
| 状态变化 | 读写哪些状态，事务与一致性边界在哪里 |
| 输出与反馈 | 返回、事件、文件或可观察状态是什么 |
| 失败与恢复 | 错误怎样传播，重试、幂等、补偿和人工介入是否存在 |
| 回验依据 | 路径、符号、配置、数据定义或运行证据，适用版本与环境 |

仅展开适用机制。没有确认重试、幂等或事务策略时写未知，不按常见架构模式补造；已确认缺少机制时再说明其影响。

### 公共机制

共享权限、审计、事务、错误处理或序列化等机制集中说明输入、结果、约束与适用范围。业务路径只标明经过何处及特例，具体公共规则通过引用关联。

局部实现不等于架构决定。机制若影响多个构件的边界或关键质量，在 [[系统架构拆法]] 中解释取舍，在实现中保留具体执行与证据。

### 数据结构

| 数据块内容 | 记录要求 |
|---|---|
| 逻辑责任 | 属于哪个业务对象或机制，谁负责写入和解释 |
| 物理分布 | 位于哪些库、表、文件、索引或消息主题 |
| 关系与标识 | 主键、关联键、基数、引用方向及状态关系 |
| 读写与生命周期 | 主要生产者、消费者、保留与清理规则 |
| 证据 | 数据定义、迁移、查询或代码依据及适用时点 |

数据块可以先按对象、聚合或访问路径组织，再映射物理库。物理库本身形成独立维护边界时也可以按库切；不预设“每库一页”。

关系表和 ER 图按问题选用。明确区分数据库外键、代码关联与业务逻辑关系，图上的连线不能自动解释为数据库约束。跨块主链由共同入口维护，各块记录自身事实。

### 动作粒度

一动作一页适用于具有独立前置、状态变化、交互和失败边界的动作，不限某类引擎。连续动作若必须一起阅读才成立，先保留同一条路径。

长路径可先按阶段分节，再判断是否有独立机制值得拆页。代码量、接口数量或页面长度只能提示检查，不能单独证明拆分合理。

### 证据范围

现状记录说明观察环境、日期或版本，以及证据可支持到什么范围。活跃工程无需整体冻结，但关键行为应能回到具体依据；源码存在证明有实现，实际运行证据才能进一步支持运行行为。

文档、代码、配置与运行结果冲突时，先核对版本、特性开关和输入条件，不规定某一类证据在所有问题上天然优先。

## 操作规则

1. 从功能、故事或故障问题选择关键行为，明确当前观察范围。
2. 在路径、组件机制、数据生命周期中选择主轴，列出入口及输出。
3. 沿关键执行核对状态变化、契约、失败传播和恢复责任，补齐回验证据。
4. 抽取公共机制，建立数据责任与物理分布记录；区分逻辑关系和真实约束。
5. 按独立解释和维护需要拆节或拆页，关联对应功能与架构，不复制操作指南。
6. 用一组真实输入或已存在运行记录核查路径；无法运行时说明可信边界，不声称已经实测。

### 验收判据

- 能说明技术触发如何到达结果，构件、契约与状态变化相互关联。
- 当前实现可回验，观测范围明确，目标方案和未知机制没有冒充事实。
- 数据块有责任、分布、关系与证据；逻辑关联没有被误报为数据库外键。
- 公共机制只维护一次，路径中的特例与关键失败责任仍可查。
- 动作粒度由独立边界决定，没有仅按界面步骤或物理代码层切成碎页。

## 可信边界

静态代码与数据定义不能覆盖所有运行行为，运行样本也不能覆盖全部输入、环境和并发条件。取证方式需要与所作断言匹配。

技术行为链、数据块与公共机制是可选分解方式，不要求每个系统同时建立完整三套页面；实现知识的可回验性也不等于性能、安全或业务正确性已经得到证明。
