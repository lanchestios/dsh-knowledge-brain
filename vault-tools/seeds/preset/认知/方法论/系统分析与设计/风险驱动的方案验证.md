## 定义

风险驱动的方案验证是一套先找出最可能使方案不成立的假设，再选择足以暴露问题的实验或分析，以有限投入支持继续、修改或停止决定的方法。它从“出现什么证据就应放弃当前判断”开始设计验证，让结果有机会改变选择。

风险可以来自用户行为、业务规则、组织协作、法律条件或技术能力。演示能运行只是某种证据，只有实验检验了决定方案成立的假设，才能据此判断相应风险。

### 适用任务

| 任务信号 | 优先验证什么 |
|---|---|
| 方案依赖尚未做过的集成 | 必需能力、语义与失败处理是否可实现？ |
| 一个指标决定技术选型 | 在关键条件下是否存在足以否定候选的结果？ |
| 用户价值只来自团队推测 | 目标人群是否有这种任务与可行使用路径？ |
| 依赖其他组织改变流程 | 对方是否能承诺改变，代价是否可接受？ |

### 必要输入

| 输入 | 最低要求 |
|---|---|
| 当前方案 | 要支持的任务、关键设计决定与可替代方向 |
| 成立假设 | 方案依赖什么事实，哪些目前没有证据 |
| 决策条件 | 谁决定、什么结果改变选择、可接受什么代价 |
| 实验资源 | 可用数据、参与者、环境、工具、预算及限制 |

## 出身

GOV.UK 的 alpha 实践要求只做检验最危险假设所需的最少工作，原型不必覆盖整个旅程，目标是决定哪些想法值得继续投入。探索结果也可以支持停止或重新开展发现工作。

SEI 在 2000 年发布的 ATAM 报告，把架构风险定位到决策、具体质量响应、后果与理由，并强调非风险判断依赖成立条件。2006 年的 ADD 2.0 列出模型、实验、仿真、形式分析和架构评估等检查手段，要求结果反馈到设计。

这些实践共同支持先聚焦关键未知、再选择取证办法的工作方式，但没有给出一套适合所有项目的风险分数或实验协议。

## 核心构件

| 构件 | 需要写清什么 |
|---|---|
| 风险陈述 | 哪个决定依赖什么假设，假设不成立会怎样 |
| 反证条件 | 观察到什么就足以否定该假设或当前候选 |
| 取证手段 | 为什么该手段能暴露这个问题 |
| 实验边界 | 人群、数据、环境、负载、故障及排除条件 |
| 证据记录 | 实际操作、原始结果、异常、局限与解释 |
| 决策出口 | 继续、修改、停止或因证据不足而再取证 |

反证条件应先于结果约定。例如，“接口有返回值”不足以支持集成可行；必需语义无法表达、权限得不到授权或故障无法处置，都可能使集成方案不成立。

### 取证选择

| 未知主要在哪里 | 可考虑的最小取证手段 | 仍不能直接证明 |
|---|---|---|
| 用户能否理解并完成任务 | 粗原型、任务观察与参与者反馈 | 全部人群都能成功 |
| 规则或算法能否表达 | 代表实例、边界例与简化行为原型 | 完整系统集成正确 |
| 运行质量是否可行 | 模型、仿真、实验或针对性测量 | 生产条件下持续达标 |
| 外部组织或约束是否允许 | 责任人核对、协议与可行性调查 | 未来承诺一定兑现 |

实验越简化，越需要解释省略了什么。省略的部分若本来就是主要风险，实验即使成功也没有回答问题。

### 反证示意

以下为原创情景，不含项目实测数据。

| 方案依赖的假设 | 预先约定的反证条件 | 最小实验 | 决策含义 |
|---|---|---|---|
| 遗留系统能接收必需的取消操作 | 接口无法表达取消，且无获准的替代路径 | 用代表订单核对接口与状态变化 | 修改流程或放弃该集成候选 |
| 新候选能在约定峰值下满足响应目标 | 在代表数据与资源条件下超出约定阈值 | 只搭关键链路测量，并核对错误结果 | 修改设计或比较下一候选 |

未出现反证，只表示该次尝试没有推翻假设。若缺少关键权限、样本或故障条件，应记录“证据不足”，不能归入通过。

## 操作规则

### 分析步骤

1. 列出成立假设。逐项追问：用户为什么用、规则是否成立、外部方是否配合、关键技术条件是什么；写出失败后对业务或方案的后果。
2. 选择最先处理的风险。综合失败后果、当前证据不足程度、返工代价与取证成本排序。优先处理足以使方案失效或阻塞后续投入的未知，并说明排序理由。
3. **预写反证与决策。** 写明什么结果会否定假设、触发何种修改或停止；同时约定何时因证据不足继续调查，避免结果出来后挪动判据。
4. 设计最小实验。选择能检验关键假设的手段，约定样本或环境、操作、度量、阈值、预算与停止条件；保留与主要风险有关的真实复杂性。
5. 执行并保留证据。记录实际条件与计划的偏差、原始结果、异常及失败过程。若环境无效或输入不代表目标情境，先判断实验是否有效。
6. 解释证据范围。对照反证条件，分别记录已被否定、暂未被否定和未覆盖的判断；检查一个指标改善是否损害其他关键条件。
7. 作出并传递决定。继续时限定适用条件并列出剩余风险；修改时回到相关设计；停止时说明触发依据；再取证时明确下次要补哪项证据。

不要把实验数量或原型完整度作为进度目标。

### 最小产出

| 产物 | 最低内容 |
|---|---|
| 风险卡 | 方案决定、假设、失败后果、现有证据与排序理由 |
| 实验卡 | 反证条件、样本或环境、操作、度量、阈值、预算与出口 |
| 结果记录 | 实际条件、原始证据、异常、有效性与覆盖限制 |
| 决策记录 | 继续、修改、停止或再取证，理由、责任人与剩余风险 |

证据改变架构候选时，回到[[质量属性驱动设计]]修订职责、接口和假设；证据否定用户任务或改善价值时，回到[[问题界定与需求发现]]。

### 验收判据

- 实验对应一个明确假设，能解释该假设失败为何影响方案。
- 反证条件与决策出口在执行前写清，阈值有业务依据或明确标为暂定。
- 样本、环境和操作足以检验主要假设，简化内容与未覆盖条件可见。
- 结果区分有效证据、实验失效与证据不足，失败没有被成功演示掩盖。
- 结论只覆盖实际验证范围，并说明哪些条件变化后需要重新验证。
- 已明确证据如何改变下一步投入、设计或问题判断，而非只归档结果。

## 可信边界

风险卡、反证条件、实验卡、排序与退出规则是作者对已读材料的归纳，不是材料原有的统一协议。本轮材料未给出通用样本量、概率估计或风险评分公式，具体实验必须补充领域与统计判断。

原型探索、架构分析和生产验收具有不同的证据强度。GOV.UK 的 alpha 支持继续投入决定，ATAM 识别风险与趋势；两者都不能替代生产验收。

未发现失败不等于已经证明安全或正确。输入分布、流量、外部系统、组织承诺或设计发生变化后，原结论可能失效；涉及稀有故障、长期行为与不可逆副作用时，单次最小实验尤其不足。
