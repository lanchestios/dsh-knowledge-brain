我在做什么。按业务域组织。

本页是这个区的读写规则，与 `wiki-write` 技能的 `writing.md` 叠加；两边冲突以本页为准。

## 怎么读

回答「我在做的业务域与系统现在什么样、往哪走」。

- 先定是哪个节点：名字以「平台」收尾的是业务域，以「系统」收尾的是单系统，以「矩阵」收尾的是行业矩阵。问跨平台怎么串（阶段口径、链路、数据流、域间关系）读矩阵节点；单个平台的事仍去 `系统/<平台>/`——平台平铺在 `系统/` 二层，不挂矩阵下。
- 业务域往下走两个抽屉：现状看 `业务域落地/`（已建系统、项目树），往哪走看 `业务域规划/`；单系统的规划在 `系统域规划/`。
- 功能页分两节读：怎么用看「功能与操作」，怎么实现看「实现」。
- 规划与落地有差距是常态，两边都摘上，不替调用方对照。

交回照 `wiki-read` 技能的上下文包：逐字摘原文、出处写到节标题、缺的进「没找到」。

## 和 学习/ 的差别

拆内部系统和拆外部项目用同一套方法，差别三处（见 [[业务域推进]]）：不钉基线（活仓随开发在动）、取材多一路问人与评审纪要、落点在 `系统/<域>/`。

拆内部系统的页用 `知识/知识.md` 的 `系统 / 架构类` 骨架（研习变体见 `学习/学习.md`），去掉钉基线。

## 功能 / 对接类骨架

**功能 / 对接类**（`系统/<域>/系统实现/` 的功能页、对接页、操作指南）

```
功能与操作（★ 每个功能：从哪进、怎么操作、系统反馈）→ 实现（接口、路由、调用链、存储，一节收拢）→ 没有的能力（仅语义消歧）→ 可信边界
```

操作与实现分家是这一类的铁律：操作主线只写页面与协议行为——菜单、按钮、填写项、做完系统给什么反馈；接口端点、前端路由、gRPC 链路、表名、类名是实现的形状，收进单独的「实现」节，不散进步骤里。判据：读者得先会调接口才读得懂「怎么操作」，就是实现混进了操作。

## 业务域骨架

**业务域**（`系统/<域>/`）

**名词四级：域 > 子域 > 系统 > 模块。** 前两级是业务摊谱系——切业务的摊；系统是工程实体——建出来的东西；模块是系统内的构件。命名跟着分级走：**域级以「平台」收尾，系统级以「系统」收尾**——名字自带分级，看到「平台」知道是域，看到「系统」知道是系统；子域以「域」收尾，模块叫它本来的名字。「子系统」与「单系统」不是新的一级，是系统级的两种挂法：子系统挂在域结构里，单系统不套域直接当 `系统/` 二层节点。判型看拆解的下一层，名字跟着判型走：

| 级 | 是什么 | 拆解的下一层 | 挂哪 · 长成 |
|---|---|---|---|
| 域（X平台） | 一摊业务，多个系统共支撑 | 子域、系统 | `系统/<平台>/`：域门面＋两个抽屉 |
| 子域（X域） | 域切出的子摊，形状是域的缩小版 | 还是域的形状（对象 / 流程 / 开放面） | 规划抽屉里的域页：子域门面＋三分类子页；摊大了再分层 |
| 系统（X系统） | 建出来的实体（子系统＝单系统，同此级） | 模块、功能、视图 | 域内挂 `业务域落地/`（外购一页 / 自建文件夹）或摊大的子域内按系统切片分层；不套域就当 `系统/<系统>/` |
| 模块 | 系统内的构件 | — | 构件页，平铺在所属系统或域门面旁 |

**行业矩阵在四级之外（名以「矩阵」收尾）。** 串联多个平台/系统、直接对应一个行业的信息化建设的收拢节点：不进四级谱系、不带骨架抽屉，平台仍平铺在 `系统/` 二层不挂矩阵下；矩阵收的是跨平台读法。先例 `系统/教育行业矩阵/` 长成门面加四页：`生命周期`（各条时间轴的阶段读法，阶段词取自各域页）、`全链路数据流`（主数据 owner → 业务单据链 → 人力消费的跨带供数）、`端到端链路`（按链路一条泳道，步骤行级）、`矩阵域关系`（域级连通图，下挂各域视图子页）。四页共用同一套锚、节点口径一致；单域内的对象、状态机与字段以各域域页为准。这是先例长成，不是固定骨架，`wiki check` 不查缺页。

**域与子域的差别只在层级，不在形状。** 域切成若干子摊，每个子摊是一域：判型与域同——拆下去还是对象、流程、开放面的域形状；形状是域的缩小版——子域门面收定位，三分类子页装构件。子域不带落地抽屉：系统落地与项目树归父域，规划侧的页（域内规划页、用户故事）随层走。层级由挂的位置定，不由大小定——同一摊业务挂在规划抽屉里是子域，独立成 `系统/` 二层节点就是域。

**系统内可以按域的形状拆，身份不变。** 自建系统拆到域内拆解那步会长出「域」形状的层（骨架在系统内递归）：那层用的是域的骨架，身份是系统的构件拆解，不进域的谱系——推进归系统自己的拆解路线图，不设抽屉。

**规划也分两级，不同名。** 域级（平台）的规划抽屉叫 `业务域规划/`，答整摊往哪走；系统级的规划叫 `系统域规划/`，答这个系统往哪走——二层单系统节点固定此名，装本系统的痛点、战略与规划台账；落地抽屉内的自建系统按内容命名规划页（如拆解路线图）。两级不混名：业务域规划只挂在平台下，系统域规划只挂在系统下。

一个域长成「域门面＋两个抽屉」。域门面收全景——品类与格局、域清单表与域间交互，域内细节不进门面；细节分进两个抽屉：`业务域规划/`（固定骨架）装终局设计，`业务域落地/`（固定骨架，下设项目树）装已建/在建的系统与落地项目。规划答「往哪走」，落地答「现在到哪了、差多少」；两者有差距是常态，怎么靠拢由人决策，落地门面只管把现状记全。目标形状：

```
<平台>/
├─ <平台>.md            ← 域门面：品类与格局全景、域清单
├─ 业务域规划/          ← 终局设计
│  ├─ 业务域规划.md     ← 规划门面：现状全景基线、推进规划
│  └─ <子域>/ …         ← 域页，每域按素材厚度立三分类子页
└─ 业务域落地/          ← 落地现状
   ├─ 业务域落地.md     ← 落地门面：居民表（是什么、与规划的差距）
   ├─ <外购系统>.md     ← 一页对接关系
   ├─ <自建系统>/       ← 文件夹按拆解深度生长
   └─ 项目树/           ← 落地摊的项目清单
```

**规划抽屉按域分页。** 每域长成文件夹，域门面收本域定位，构件级内容按三分类拆子页：

| 页 | 装什么 |
|---|---|
| 域门面 `<域>/<域>.md` | 定位（管什么、通行模块名）；对照多家时加模块拆分对照（各家把这摊切在哪，证据粒度一列）与口径（本域统一词、各家叫法、拆域依据）；子页导航表 |
| `领域模型` | 对象为单位：实体字段表、枚举转写、对象关系、状态机 |
| `业务流程` | 时序与主线：跨域时序、日推进与周期节拍、封账、与相邻域的接缝 |
| `系统架构` | 开放面与外部：接口分组、事件与 webhooks、外部接缝、跨系统 ID |

三张子页按素材厚度立其中几张，不搭空壳；素材另有产品层就补一张「产品架构」。摊大到一域装不下的，在域门面下按系统再分一层，层内的规划页与故事随层走。域下的系统与模块是构件页，平铺在域门面旁，用上面的系统 / 架构类骨架，不塞进三张子页。

**落地抽屉按系统分页，页型看系统性质：**

| 系统性质 | 长成 | 装什么 |
|---|---|---|
| 外购系统 | 一页 | 对接关系：它在数据链里的角色（权威源／出口）、对接面、可信边界——内部拆不到，就拆它与邻系统的关系 |
| 自建系统 | 文件夹 | 按拆解深度生长：`拆解路线图`（路线与验收线的对账，入口页）→ `模块结构`（工程构成）→ 域内拆解（按域三分类长——骨架在系统内递归）→ 构件页平铺 → `用户故事` 收底 |

**归位与生长。** 项目树归 `业务域落地/项目树/`，域节点的落地抽屉必设、项目树恒在其下——项目清单是落地摊的事，暂无项目也先立页；用户故事归对应的系统或域内部——已建系统放 `业务域落地/<系统>/` 内，规划中的域放 `业务域规划/<域>/` 内。生长从门面起手：域门面全景 → 规划门面（先有现状基线一张图也算开张）→ 域页按素材一张张立 → 落地系统出现时进落地抽屉 → 自建系统照拆解路线图推进。不搭空壳。

单系统不套域，直接当 `系统/` 的二层节点；内部照自建系统的长法生长，规划收在 `系统域规划/`。这摊长出第二个系统要入库时升格为域：改名以「平台」收尾、立域门面与两个抽屉，原系统挪进落地抽屉、`系统域规划/` 的内容并入业务域规划。

对照多家时的转写纪律：证据分档（字段级 / 行为级 / 营销页 / 缺口）进对照表与可信边界，缺的档如实标缺口；各家冲突分列不裁定；文档瑕疵逐字保留加注，不代改。

## 知识页只写现状

知识页写系统此刻的样子，不写它欠什么：未实现、规划中的能力（愿望清单、形态枚举的反面）不进知识页，归宿本域的 `系统/<域>/业务域规划/`（如「未实现的能力」清单），供迭代规划取用。页里保留的「没有」仅限语义消歧——读者可能带着别处心智来错读时点破（「转交是整体移交，不是 BPMN 委派」「没有候选组认领，全部 assignee 严格匹配」）。判据：删掉这条「没有」，读者会不会把系统读错；会错才留。

## 专名口径

一个意思一个词。分级词全库统一：域 > 子域 > 系统 > 模块（子系统＝单系统，同属系统级）。域里的系统与模块专名，全库正文只用统一词；同义的别名叫法（样本原文、行业叫法）只活在三处——术语页或门面的对照、页的可信边界、样本图与引文的逐字转写。正文里冒出第二个词指同一物时不并列混用：在术语页（或域门面）立案统一词、登记别名，然后把正文收干净；改名后旧词只作为带来源标签的别名出现。例：把「收单平台／收单结算」统一成「收单域」，别名登记进领域术语页。
