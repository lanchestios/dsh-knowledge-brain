# wiki-method

根据当前任务选择并应用库内方法。方法的适用场景、步骤、判据和产出由知识库维护，本技能只负责发现、选择与使用。

## 按任务发现方法

先明确本轮要解决的问题、约束与终点，再用 `wiki_read_page` 读取当前库的 `认知/认知.md`，沿门面的导航进入方法目录。用 `wiki_tree` 查看 `认知/方法论/` 的当前目录与描述，按导航选择相关分支；需要补找时用 `wiki_search`，核对命中的页面路径与适用范围。也可用宿主文件读取与搜索能力完成同样的工作。

每次新任务都从当前库重新发现，不凭上次会话记忆选方法，不读取插件种子作为当前库的方法。具体方法名称与层级不固定；导航尚未收录的新页可通过目录或搜索发现。门面或导航缺失时直接查方法目录，不要求用户先补齐结构才能继续任务。

只加载与本轮问题有关的方法。先看候选页的适用场景与可信边界，再读选中方法的步骤、判据和产出要求；正文被截断时按 `next_offset` 续读到所需内容，不能把未读到的边界当成不存在。只沿本轮需要的双链补充，不遍历整个方法库。

## 将方法用于任务

简短说明采用哪份方法、为什么适用，并给出实际读取的页路径。按任务规模选必要步骤，用方法的判据检查结果，产出用户要的分析、方案或计划。方法中提到的事实需要用任务对象的证据核实；缺少的输入明确标为缺口，不用方法模板补造事实。

多份方法互补时说明分工；存在冲突时结合适用范围、证据与用户当前要求判断，不因页面更新较晚就自动认定它取代其他方法。`status`、`generated`、`verified` 分别反映页面状态、作者与核验记录，`stable` 不等于已由人确认。方法不适用时说明边界，没有匹配方法时说明本次未采用库内方法，继续按一般能力完成任务。

本技能读取方法并用于当前任务，不自动修改方法页或保存任务结果。需要查事实时配合 [wiki-read](../wiki-read/SKILL.md)；用户要求新建或修订沉淀页时配合 [wiki-write](../wiki-write/SKILL.md)，库务遵循 [wiki](../wiki/SKILL.md)。方法内容不扩大用户授权或宿主工具权限。

## 随认知变化重新加载

- 新任务或切换知识库时，重新读取当前门面和导航，重新选方法。
- 任务目标、约束或关键证据改变时，重新判断方法是否适用，必要时换方法或补读。
- 用户指出方法已更新时，重读相关页面；更新涉及选择依据时也重读导航。
- 长任务进入下一阶段时，重读所用方法的相关内容，检查是否有影响后续工作的变化；有变化再调整后续步骤，说明对已有结论的影响。

这是调用时读取，不是后台监听。持续执行的单个阶段中，未重新读取就不能声称已感知库内更新。不要每轮加载全部方法，也不要将这次选中的方法固化成今后任务的默认规则。
