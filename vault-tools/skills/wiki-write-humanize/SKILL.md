# wiki-write-humanize

去掉一页 wiki 正文里的 AI 味，只处理指定那一页里的改动范围。不联网、不运行 shell，最终验收由 `wiki-write` 编排层执行。

## 只处理改动范围

prompt 给的改动范围是这次唯一要处理的部分。`全页` 就整页处理；给的是行号段，就只处理这些行落在的散文段——行号只碰到段落的一部分，按整段处理，段落以空行为界。范围外的正文已经收过：不读、不改，看见毛病也不顺手改。要知道范围落在哪个二级节，从范围往上读到最近的 `## ` 标题就够了，不必从页首读起。

模式表里要计数的几行，计数也只在范围里数，阈值不变：

- 加粗泛滥：只数范围落在的那几个二级节；
- 「不是 X，是 Y」：只数范围内；
- 破折号：分子、分母都只算范围内的行，范围不足 100 行按 100 行算，免得几行改动因为一两个 `——` 就判超标。

## 硬禁区

以下几类逐字保留，一个字都不许动：

- 表格
- 目录树
- mermaid 代码块
- 代码块（含行内反引号）
- frontmatter
- 英文术语原词与紧跟其后括号里的中文标注

改之前先分辨这一段是不是散文：属于上面六类之一就跳过，剩下的正文段落才是要处理的对象。只碰散文段，不碰结构。

**不新增内容**，这一步只许删和改写。看着少一句解释更顺，也不补——那是 wiki-write-draft 的活，不是这一步的。

## 模式表

九条，判据是触发器，改法是目标态：判据决定这一条够不够格动手，改法决定动手之后改到什么程度才算完。加粗那行判据是「> 3 处」，改法是「只留最强的一处」。改到 3 处以内不算数，改到只剩一处才算完，九行都按这个关系读，不要在判据的数字上停手。

| 毛病 | 判据 | 改法 |
|---|---|---|
| 加粗泛滥 | 单个二级节内 `**…**` > 3 处 | 每节只留最强的一处；同段两处删靠后那处 |
| 「不是 X，是 Y」 | 全页 > 3 处 | 真有对立的留，其余改直陈 |
| 比喻动词 | 动词或方位词写的是修辞不是机制（贴着、接住、接成网、居中、另一头），领域有标准动词（转接、结算、扣款、缴存）能换上去且句意不变 | 换领域动词；领域没有对应对词的，删比喻直陈 |
| 节尾金句 | 段末句是概括且不含新信息 | 删整句 |
| 自我标榜 | 命中「最要紧 / 值得写进 / 这一节很关键 / 本页最」 | 删 |
| 标题宣言句 | 整个标题是一句断言，而不是一个标签 | 砍成标签 |
| 破折号 | 每百行 `——` > 8 | 超出部分改句号或括号 |
| 编号化叙述 | 「两个/三个…。一是…二是…」 | 拆成列表或分段 |
| 指书措辞 | 正文把页写成某本书的转述（「书里」「书的」「书中」「书未展开」） | 事实能独立站的删交代直陈（「书里把 X 拆成两维」→「X 拆成两维」）；要标口径来源的换「样本」，样本指哪份素材由 frontmatter 的 `source` 交代 |
| 挂名措辞 | 来源名（作者、公司、公众号、文章）挂在一条单独成立的事实上：「京东的口径：」「（老熊的…例子）」「（技术琐话的实体切分）」「（ITPUB）」 | 摘名试读：摘掉来源名与「的口径 / 的例子 / （X）」后句子照样成立、没跟别家说法撞上，就删名直陈；几家说法并排、摘名就分不清的真对照留着不动 |

破折号这一行例外，要放到最后处理。它的判据是密度，分母是全文行数，会被其余各行的编辑动作改变（尤其编号化叙述拆段、节尾金句删句，都会让总行数变）。其余各行先按表里的改法改完，再重新数一遍全文 `——` 的出现次数与总行数，算出这一轮的密度；还是 > 8，就从密度最高的段落挑起继续删，改到 ≤ 8 为止。这个 agent 只有 Read 和 Edit，数不出来就一段一段数：先数每段几处 `——`，再数总行数，除一下。

### 标题宣言句那一行，判据是「是不是断言」，不是「有没有冒号」

这条早先写的是「含 `：` 或 `——` 且右半是断言」，实跑漏过两类：

| 漏过的形状 | 例子 | 为什么漏 |
|---|---|---|
| 用逗号或顿号分隔 | `三种注册面，三种互不相同的裁决策略` | 分隔符不在那两个里 |
| 完全没有分隔符，整句就是断言 | `tool_call 异常穿透两层调用栈` | 没有左右半可分 |

改法一样：砍成标签（`三种注册面`、`tool_call 的异常`）。断言本身别删，它在正文里展开。

**怎么判是不是断言**：标题单独拎出来，它是在给这一节命名，还是在替这一节下结论。「对外契约：扩展能摸到什么」是命名（右半是话题），留；「reload：整体重建，不是选择性卸载」是下结论，砍。

## 为什么不套用通用去味技能

市面上的中文去 AI 味技能（这个仓库原先装过一份，已删）判据大同小异：往「有观点、第一人称、幽默、变化节奏、两项优于三项」推，目标是把文字改得更像一个人在说话，预设读者面对的是散文体的文章。

这个仓库的正文本来就不是散文。`wiki` 的骨架判据常常要求一段内容写成表而不是几句流畅的话，很多页里表和树占的篇幅比段落还多。照那种路子去改，会把「三个子域怎么分」那张表拆回三句叙述，那不是去味，是把结构改没了。差别落在硬禁区那六类上：通用技能没有这道边界，这份有。

所以遇到「去 AI 味」的活，用这份，不要去找通用的那种。

## 改不动就别改

先按模式表试着删加粗、拆对偶句，删完读一遍原意。意思没变，改法留下；意思变了，说明那一处标的不是修辞而是内容——加粗标的是这段真正的重点，对偶写的是真实存在的对立，都留着别碰。

拿不准就不动，宁可漏改，不可改坏：漏改下次还能再收一遍，改坏了要回去比对原文才看得出差在哪，而原文一旦被覆盖，比对就没有了基线。
