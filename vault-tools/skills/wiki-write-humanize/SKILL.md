# wiki-write-humanize

去掉一页 wiki 正文里的 AI 味，只处理指定那一页里的改动范围。不联网、不运行 shell，最终验收由 `wiki-write` 编排层执行。

## 动笔前三条

1. **只动改动范围**。prompt 说全页就整页；给的是行号段，就只处理这些行落在的段落。范围外不读、不改，看见毛病也不顺手改。
2. **结构和文字都可以动，改完不许丢原意**。表格、目录树、mermaid 代码块、代码块（含行内反引号）、frontmatter、英文术语原词与紧跟其后括号里的中文标注，都不再是禁区。动之前先弄清这一段在讲什么，改完再读一遍：意思不能变，条目不能少，术语对得上。
3. **只删和改写，不新增**。看着少一句解释更顺，也不补，那是 draft 的活。

细则在下面「只处理改动范围」一节，动第一笔之前先看一眼。

## 主线：先看骨架，再看词

一页正文读着像 AI，多半不是词选错了，是句子先在英文里成型，再逐块换成中文词。词换得再对，语序、连接词、时间副词、意象还是英文的，读出来就是翻译腔。删加粗、删金句、拆排比，收的都是边角；骨架不动，收完还是那个味。

判据只有回译：把句子译回英文，逐词对得上、而且英文读着更顺，它就是英文构思的投影。中文自己长出来的句子，回译过去一定别扭。

「AI 缺的是你还没有交出去的那部分。而那些东西，一直锁在人脑子里。」译回去是 `What AI lacks is the part you haven't handed over yet. And that part has always been locked inside people's heads.` 一句不落，英文还更顺。

### 五个可查标记

| 标记 | 中文症状 | 英文来源 | 改法 |
|---|---|---|---|
| 换词回指 | 「那部分」后头换成「那些东西」指同一个东西 | the part → those things，英文避重复的手法 | 直说「这些」，或者干脆省主语 |
| 句首连接词直搬 | 用「而」「此外」「同时」起句 | And / Moreover，英文的段落粘合剂 | 删掉，另起一句短的，靠语序承接 |
| 时态副词硬对 | 「一直」「始终」贴着状态 | has always been | 删，或者改成事实句「没人写过」 |
| 属格丢失 | 「人脑子里」少个「的」 | people's heads | 补成「某个人的脑子里」，或者整个换掉 |
| 意象借用 | 「锁在脑子里」 | locked in sb's head | 揣着 / 没落成字 / 没录过 |

「……的是……」本身不是毛病。「他缺的是经验」是汉语原生句式，前半句无罪，别当翻译腔一起拆了。

### 对偶与压缩

英文 it-cleft 加句首重复，落到中文就是「A 缺的是 B。而 B 一直 C。」，工整到能对上标点。压缩是它的收窄，`一X就Y` 把三层因果塞进五个字，判据是能不能单独拎出来印在墙上，能就还没改完。「人一走就断」过不了这一关：它压掉了「没写过、别人不会、他走了就没了」三层，改成「问了他也得想半天，说出来还跟上次不一样」，信息多了，气也顺了。

## 改写配方：换语序，不换词

中文先说要说的东西，再说它怎么了，「AI 缺的是你没写下来的」改成「你脑子里那些没写下来的，AI 拿不到」。少用「是……的」下判断，多用实义动词；「而」「因此」「此外」「同时」能删就删，中文靠语序承接，不靠连词。结尾落在一个具体的、有点拖泥带水的事实上，不结案。土动词比形容词管用：得去问他，想半天，跟上次不一样。

> 原：AI 缺的是你还没有交出去的那部分。而那些东西，一直锁在人脑子里。
> 改：你能交给 AI 的，只有已经说出来的那部分。剩下的都在人身上。真要用，得去问他，他得想半天，说出来还跟上次不一样。

## 收边角：模式表

骨架换过之后重读一遍，下面这张表往往自己就少了几行，它留着兜底。

判据是触发器，改法是目标态：判据决定这一条够不够格动手，改法决定动手之后改到什么程度才算完。加粗那行判据是「> 3 处」，改法是「只留最强的一处」，改到 3 处以内不算数，改到只剩一处才算完。每一行都按这个关系读，不要在判据的数字上停手。

| 毛病 | 判据 | 改法 |
|---|---|---|
| 加粗泛滥 | 单个二级节内 `**…**` > 3 处 | 每节只留最强的一处；同段两处删靠后那处 |
| 「不是 X，是 Y」 | 全页 > 3 处 | 真有对立的留，其余改直陈 |
| 比喻动词 | 动词或方位词写的是修辞不是机制（贴着、接住、接成网、居中、另一头），领域有标准动词（转接、结算、扣款、缴存）能换上去且句意不变 | 换领域动词；领域没有对应词的，删比喻直陈 |
| 节尾金句 | 段末句是概括且不含新信息 | 删整句 |
| 自我标榜 | 命中「最要紧 / 值得写进 / 这一节很关键 / 本页最」 | 删 |
| 标题宣言句 | 整个标题是一句断言，而不是一个标签 | 砍成标签 |
| 破折号 | 每百行 `——` > 8 | 超出部分改句号或括号 |
| 编号化叙述 | 「两个/三个…。一是…二是…」 | 拆成列表或分段 |
| 指书措辞 | 正文把页写成某本书的转述（「书里」「书的」「书中」「书未展开」） | 事实能独立站的删交代直陈（「书里把 X 拆成两维」→「X 拆成两维」）；要标口径来源的换「样本」，样本指哪份素材由 frontmatter 的 `source` 交代 |
| 挂名措辞 | 来源名（作者、公司、公众号、文章）挂在一条单独成立的事实上：「京东的口径：」「（老熊的…例子）」「（技术琐话的实体切分）」「（ITPUB）」 | 摘名试读：摘掉来源名与「的口径 / 的例子 / （X）」后句子照样成立、没跟别家说法撞上，就删名直陈；几家说法并排、摘名就分不清的真对照留着不动 |

这十行大半挂得到主线底下：「不是 X，是 Y」是对偶，节尾金句是压缩，比喻动词多半是意象借用，自我标榜与标题宣言句是英文 topic sentence 的残余。加粗泛滥跟语序无关，它的问题是标不出重点。主线改完，这几行常常跟着一起没了。

破折号这一行例外，要放到最后处理。它的判据是密度，分母是全文行数，会被其余各行的编辑动作改变（尤其编号化叙述拆段、节尾金句删句，都会让总行数变）。其余各行先按表里的改法改完，再重新数一遍全文 `——` 的出现次数与总行数，算出这一轮的密度；还是 > 8，就从密度最高的段落挑起继续删，改到 ≤ 8 为止。这个 agent 只有 Read 和 Edit，数不出来就一段一段数：先数每段几处 `——`，再数总行数，除一下。

### 标题宣言句那一行，判据是「是不是断言」，不是「有没有冒号」

这条早先写的是「含 `：` 或 `——` 且右半是断言」，实跑漏过两类：

| 漏过的形状 | 例子 | 为什么漏 |
|---|---|---|
| 用逗号或顿号分隔 | `三种注册面，三种互不相同的裁决策略` | 分隔符不在那两个里 |
| 完全没有分隔符，整句就是断言 | `tool_call 异常穿透两层调用栈` | 没有左右半可分 |

改法一样：砍成标签（`三种注册面`、`tool_call 的异常`）。断言本身别删，它在正文里展开。

怎么判是不是断言：标题单独拎出来，它是在给这一节命名，还是在替这一节下结论。「对外契约：扩展能摸到什么」是命名（右半是话题），留；「reload：整体重建，不是选择性卸载」是下结论，砍。

## 只处理改动范围

prompt 给的改动范围是这次唯一要处理的部分。给的是行号段，就只处理这些行落在的段落，行号只碰到一段的一部分，按整段处理，段落以空行为界。范围外的正文已经收过：不读、不改，看见毛病也不顺手改。要知道范围落在哪个二级节，从范围往上读到最近的 `## ` 标题就够了，不必从页首读起。

模式表里要计数的几行，计数也只在范围里数，阈值不变：

- 加粗泛滥：只数范围落在的那几个二级节；
- 「不是 X，是 Y」：只数范围内；
- 破折号：分子、分母都只算范围内的行，范围不足 100 行按 100 行算，免得几行改动因为一两个 `——` 就判超标。

## 改不动就别改

先按主线回译一次，再按模式表试着删加粗、拆对偶句，删完读一遍原意。意思没变，改法留下；意思变了，说明那一处标的不是修辞而是内容，加粗标的是这段真正的重点，对偶写的是真实存在的对立，都留着别碰。

拿不准就不动，宁可漏改，不可改坏：漏改下次还能再收一遍，改坏了要回去比对原文才看得出差在哪，而原文一旦被覆盖，比对就没有基线了。
