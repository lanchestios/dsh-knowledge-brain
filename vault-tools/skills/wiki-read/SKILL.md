# wiki-read

给调用方补库内上下文。**你交回的是材料，不是答案**：答案、分析、对照、结论都由调用方自己做。

## 先定区，再读门面

| 问的是 | 去 | 读门面的「怎么读」 |
|---|---|---|
| 项目、系统现状、业务域规划 | `系统/` | `系统/系统.md` |
| 领域概念、书里的方法、判据 | `知识/` | `知识/知识.md` |
| 外部系统在某个版本上怎么造、怎么用 | `学习/` | `学习/学习.md` |
| 我怎么看、我的方法论与原则 | `认知/` | `认知/认知.md` |
| 当时发生了什么 | `经历/` | `经历/经历.md` |

命中几个区就读几个门面，每个门面先读它的 `## 怎么读` 一节，照那一节在区里找。门面还没有这一节时，按上表的判据找，并在「没找到」里注一句「<区> 门面缺怎么读」。

## 只读沉淀页

- 读：五个区里的页。用 `wiki_search` / `wiki_read_page` / `wiki_backlinks` / `wiki_tree` / `wiki_tags`，或 `Read` / `Grep` / `Glob`。
- 不读：`.wiki/review/` 账本（写作过程账，不是知识）、`raw/` 素材（原件，不是沉淀）。不用 `wiki_raw`。调用方明确要素材原文时再给。
- 不写任何文件，不联网。

## 交回的形状：上下文包

```markdown
## <问题或任务的一句话复述>

### <页路径>（<区>，status: <stable|draft>[，基线 <版本>]）
> 原文片段，逐字摘录，不改写
（所在节：<## / ### 节标题>；与本问题的关系：一句话）

### 没找到
- <问题里的哪一块，库里没有对应内容>
```

- 每个片段都是原页里能逐字 grep 到的一段连续原文。要压缩就少摘几段、或摘短一点的连续原文，不改写摘下来的那段，引号里不用「……」拼接两处原文。
- 定位只写节标题，不写行号：`wiki_read_page` 按字符偏移返回，行号对不上。
- 「与本问题的关系」只说这段为什么相关，不评价对错、新旧、好坏，不统计，不对照。看出页与页之间有矛盾或过时，把两段都摘上，让调用方自己判。
- **调用方就是你自己这个会话时**（主会话、Lark 问答），上下文包只作内部材料：照它组织答案，答案按调用方自己的口径写，包本身不原样发给提问的人。
- `### 没找到` 必须有。没有缺口写「无」。读到一半没读完的页也记在这里（「<页> 只读了 <节>」）。

## 什么时候派 agent

默认在你自己的会话里照本技能查。预计要读很多页（跨区，或者一个区要沿谱系往下读好几层），又不想让读页过程占满会话时，可以调用宿主通用子智能体。prompt 给出本技能 `SKILL.md` 的绝对路径、库根与具体问题，要求它先读取技能，只读沉淀页、不写文件、不联网，交回上面这个上下文包。技能路径从当前已加载的本文件位置取得，不能假定子智能体继承了本会话的技能。

**Lark 问答会话不派子智能体，一律在本会话里查。**
