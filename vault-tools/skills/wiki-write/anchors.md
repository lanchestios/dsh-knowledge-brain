# 锚点

页里断言外部代码（类名、文件路径、配置键）时读，主要是 `学习/` 的研习页。这类断言最容易编造，编出来和真的一样。`wiki page anchor <路径>` 抽出页里反引号包的标识符，逐个到钉死的基线 commit 里 `git grep`，查不到即判为编造。

## 先钉基线

**拆一个系统之前先钉基线，没钉不开写。** 基线在 `.wiki/anchors.conf`，按路径前缀分段，一行一个仓：

```
[学习/<System>]
<名字>    raw/project/<名字>    <钉死的 commit 全长 sha>
```

- commit 必须钉死，不写分支名。
- 外部项目克隆与练习 demo 仓放 `raw/project/<名字>`，与 `book/`、`document/` 同层；raw/ 整个不入库——克隆被提交进来的话，`git grep HEAD` 会让所有标识符在本仓库命中，校验从此全过。这条依赖 raw/ 留在 .gitignore。`~` 路径会展开，相对路径按仓库根解析。
- 内部系统（`系统/`）不钉基线：活仓随开发在动，钉住的那个 commit 对写作没有意义，段落不配就是不校验。

## 查什么

只查四种形状：

| 形状 | 例 |
|---|---|
| 驼峰类名（可带 `.java` / `.py` / `.ts` / `.tsx`） | `MetricType`、`AtomicMetricExecutor.java` |
| 全大写枚举值（≥3 位） | `ATOMIC`、`PREV_PERIOD` |
| snake_case（含下划线） | `query_metric` |
| 含 `/` 的路径 | `src/agents/__init__.py` |

不查单个小写词（易和普通词撞）、带空格的命令、代码块内容（示例，不是断言）。所以保证是单向的：查到的成立，没查的不保证。

## 硬规则

「什么都没查却报通过」会让人以为核过了，比报错更坏：

- 基线仓不存在、commit 查不到、配置格式错：硬失败，不降级放行。
- 给的页都不在任何配置段下（一页没查）：非零退出。

豁免写在页里：`<!-- 锚点豁免: <token> —— <理由> -->`，没写理由的不认。

`wiki check` 不含锚点校验：check 是纯结构校验，不依赖外部仓。
