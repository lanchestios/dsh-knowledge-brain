# 写作

写或改一页正文时读。这里只列跨区规则。**动笔前先读落点区的门面 `<区>/<区>.md`**：区专属的骨架、例外、验收和方法页指路都在那里，与本文件叠加，冲突以门面为准。四节按写作时序排：先定什么进正文，再定节与页的组织，再措辞，最后配图。

## 归属：什么进正文

**按概念切，不按来源切。** 一页写一个概念，不是一份素材的读后感。出现这些就是按来源切了，重写：标题是素材名；`description` 写「XX 的核心提炼」；正文说「本页是 XX 的提炼」；章节顺序跟着素材走。区门面可以声明例外（比如按时间记流水的类目）。

**页不为自足而复读，导航交给装置。** 标题命名结构、链接指向定义、表里的格记连线、章序管先后，指路是这些装置的事，散文不代劳；事实只住一个家，别处已有一份，就不为「不点链接也读得顺」再抄一份。页面自述（「本 wiki 沿什么组织」）、嵌入件清单、格子里搬链接那头的性质、预告与复读后文的话，都不进正文；结构确是领域里的东西，就起个名字立成章节（如「分类法：任务 × 函数」）。判据：一句话主语是页——本页怎么组织、这表怎么读、那个名字在哪页——就不写，主语是事才写。

**正文不带素材的定位信息。** 章节号、页码、Part、「术语表」这类书内位置，阅读进度，核对了哪几章，都不进沉淀页。来源由 `source` 承担，是否属实由 `verified` 记录。书名、作者、年份可以写。

| 写 | 不写 |
|---|---|
| 「精粹把设计规则归纳成四条」 | 「精粹第 5 章把设计规则归纳成四条」 |
| 「前八种出自蓝皮书，Partnership 是精粹补的」 | 「前八种出自蓝皮书第 14 章（Partnership 是精粹第 4 章补的）」 |
| 表格列到「管什么」为止 | 再加一列「出处」逐行写 `蓝 15` |

「这条是我的归纳，不是原著说法」这类性质区别，写进 `可信边界`。

**正文不把内容推迟给素材。** 「全量清单在素材，此处按族归并」「详见素材」这类句子不写：`raw/` 不支持搜索，指给素材的内容读者到不了。正文指名要用的清单、码表、模板必须沉进正文；一份太长就整份向下拆成子页，双链相认，不在原地留「在素材」的空指。判据：拿着这页干活还得去翻 `raw/`，就是漏沉。

**不写「对本仓库的意义」这类落地节。** 有用的内容去它该去的地方：判据进 `认知/原则/`，做法进 `认知/方法论/`，域的决定进 `系统/<域>/`。

## 结构：节与页

**先判信息类型，再选形式。**

| 这段是什么 | 写成 |
|---|---|
| 结构（由哪些部件组成） | 目录树 + 表 |
| 分类、取值集合、字段 | 表 |
| 步骤 | 编号列表 |
| 事实、参数、限值 | 表 |
| 概念、原则、过程 | 散文，一段一件事 |

最常见的错误是把结构写成散文。

**参考和解释分开。** 「是什么」和「为什么这么设计」可以同页，但分节，不揉进同一句。

**一节一件事，标题就是它的标签。** 标题写不出 3–5 字的准确概括，说明混了两件事，拆开。

**首段独立成篇。** 脱离全文也读得懂，说清是什么、谁提的、解决什么，最重要的先说。不写本页和素材的关系。

**章末必写 `可信边界`。** 反例、失败模式、被质疑的依据、作者承认的限度、出处限制（原始文献没取到、只有二手论证）。只记结论就成了广告。

**正文不立 `待办清单`。** 对这页文本还欠人的动作（待补的一节、待改写句、标题待重拟、译名待统一）、删句的账与判过留的备忘都不进正文，记在库根 `.wiki/review/` 与页同路径的账本里：账本三节依次是 `待办清单`、`删句账`、`判过留的`，格式见 `wiki-write-review` 技能。分界还是主语判据：正文的 `可信边界` 主语是事，讲这条知识可靠到什么程度、能搬到多远，长期在，新证据进来就改写；账本的 `待办清单` 主语是页，讲编排与措辞还欠什么动作，做完就删。

### 骨架按主题类型固定

同类主题用同一副骨架，才能横向比较。骨架定义在落点区门面 `<区>/<区>.md`，按主题类型选一副；门面里没有对得上的类型，停下来问人，定完写回那个门面。

## 风格：词与句

### 术语：英文为主，中文标注

外部专有名词保留英文原词：技术术语、产品名、规范名、人名。译过的词搜不到原文，也对不上别人的说法。中文只用来写自己的话和自己的章节名。所以是 `知识/数据工程/Palantir Ontology.md`，不是 `帕兰提尔本体.md`。

英文后面用括号标中文：

```
Bounded Context（限界上下文）    ✓
限界上下文（Bounded Context）    ✗ 主次颠倒
Bounded Context                  ✗ 读者得自己配对
限界上下文                       ✗ 回查不到
```

- **何时标**：每个小节内首次出现标一次；参考表每行都标，因为表是跳读的。
- **不标的四类**：产品名（`Workshop`、`Foundry`）、规范与方法名（`OKF`、`Diátaxis`）、人名、编程语言的通用类型与关键字（`String`、`Boolean`）。判据：概念术语有中文名，被命名的东西没有。原文自己不译的也不译。
- **中文从哪来**：每个领域只认一个权威，不自己编。有官方中文文档的产品以官方为准；机器学习以人民邮电出版社《深度学习》中文版书后的术语表为准。权威没收的取通行译名，都没有才直译。别的来源给了不同译法，一律不采、不并列。官方中文是机器翻译的，把中文版写进 `source`。
- **不标依据，不收词源**：页里只写选定的中文。不写「直译」「通行译名」「出自某术语表」这类依据标签，不设「译名取的哪一家」节，也不在术语表、名词解释里收词的出处与谁提出。方法、系统页骨架里的「出身」讲的是这个东西为解决什么而生，照旧写，不在此列。
- **文件名和标题只用英文原词**，标注只出现在正文。

**先具体，后抽象。** 一句话先把最具体的说法给出来——谁、对什么、干什么；抽象名词、它在流程里充当的角色、行话随后补。判据：这句话要读者先懂某个流程或框架才读得懂，就拆开重写，把不依赖那个流程的部分放在前面。适用于全页任何一句，不只是定义句和段首。

| 写 | 不写 |
|---|---|
| 「Loss 衡量模型的预测与正确答案之间的差距；训练就是不断调参数，把这个差距压到最小」 | 「Loss 是训练时被最小化的那个标量，衡量模型在训练数据上做得多差」 |
| 「训练循环每步做四件事：前向、算 loss、反向传播、更新参数」 | 「训练循环以迭代方式对目标函数执行基于梯度的参数优化」 |

**直给的说法盖不全时，逐场景列准，不往抽象里收。** 一句直给话只对大部分场景成立时，不为了全覆盖把它改抽象，而是保留它，再按场景把准确版本列出来。Loss 门面按任务列「预测 / 正确答案 / 差距」那张表即此。

**写现状，不记演化。** 页面维护的是主题当前样子的结构化描述——是什么、怎么工作。版本引入史与变更叙事不写：「V2.8.0 起引入」「V3.1.0 时为 warning、后改为 error」「曾覆盖同意/拒绝，已收窄」这类句子里，版本号和「起/曾/此后/迁入」只在讲变化，删掉它们剩下的才是知识。日期与勘误标注同收：「（2026-07-16 新增）」「2026-07-01 修正」「此前误记 34」记的是这条知识何时进库、进库前对过没有——库默认自己就是最权威、最新的，不替自己标日期，标注删掉，核实经过进账本。判据：把版本、日期与勘误标记拿掉，句子还成立就只留剩下的；整句只剩「什么变成了什么」或「何时记下的」的，整句删。例外照写：`@Deprecated` 等代码里现存的标注、「新旧两个入口并存、前端走新的」这类并存现状、「早期数据没写该列所以查不到」这类历史数据边界——它们是现状的一部分。
