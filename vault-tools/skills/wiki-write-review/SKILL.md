# wiki-write-review

把一页 wiki 正文里的非知识内容删掉，只处理指定那一页里的改动范围：欠人的动作与过程账都进 `.wiki/review/` 里与页同路径的账本，正文只剩知识。

## 只处理改动范围

prompt 给的改动范围是这次唯一要判的部分。`全页` 就整页判；给的是行号段，就只判这些行落在的句子与标题——行号只碰到一句的一部分，按整句判，碰到表格按整张表看。范围外的正文已经收过：不读、不判，看见毛病也不顺手删。

范围外只读账本：开工照旧先读，「判过留的」直接跳过，「待办清单」里已有的不重复立条。

## 一句话判据

是知识本身的留，非知识的删。操作化成一问：**这句话的主语是页，还是事。**

主语是页：句子说的是写作这件事本身该怎么安排——放哪一页、留没留、重不重复、动没动。主语是事：句子说的是被记录的那个系统或领域本身的状态，包括这个领域还有什么没定。

判到就动手，动手到什么程度算完看下面对照表：删的那一行要删到正文里这句话彻底消失，留的那一行要留到一个字都没有改动。

## 对照表

| | 例 | 处置 |
|---|---|---|
| 主语是页 | 「本页不重复」「逐层详述各占一页」「取舍未定之前正文不动」「还缺一节讲…」 | 删 → 记账（欠人的动作另进账本待办清单） |
| 主语是事 | 「⚠️ ③④⑤ 的通信方向、契约与谁主导协调还没定」 | 留 |
| 指源交代 | 「书里叫 X」「书的全景表」「书未展开」「京东的口径：」「（老熊的收单清算例子）」「（技术琐话的实体切分）」——出处交代混在正文里，书、人、公司、文章都算 | 删交代留事实；来源限定不留正文——出处登记进 frontmatter 的 `source`，核实不了的进账本 |
| 真对照 | 「清结算系统内部（京东）只算不划 / 清算主体（老熊）算和划都在清算里」「京东是另一种接法」——几家说法并排，摘掉名字就分不清谁是谁 | 留 |

删的完成态：原句从正文里消失，账本「删句账」里有对应条目；其中欠人的动作（补一节、重拟标题…）另在账本 `待办清单` 立条。留的完成态：原句连标点都不改，照抄一遍也看不出改过。

同一句里混合着两种主语时，按从句边界拆，不按整句或整行删。例如「由于取舍未定，正文暂不改动，两套框架都在讲依赖」——三个逗号隔开的分句没有句号分界：中间「正文暂不改动」主语是页，删；前后「取舍未定」「两套框架都在讲依赖」主语是事，留。**切完剩下的两半接起来要读得通**，读不通就是切错了位置，宁可整句留着不切。

**指源的交代不看主语，直接收。** 「书里叫收单核心」的主语确实是书，看着像「主语是事」，但它交代的是证据来路，不是系统本身：沉淀页是多来源的汇总，不是某一份素材的转述，正文不提出处——库默认自己就是最权威、最新的，出处与进库时间是过程账，不是知识。书名、作者（老熊）、公司（京东）、公众号或文章（技术琐话、ITPUB）、素材与代码出处（javadoc、飞书文档）、日期与勘误标注（「2026-07-16 新增」「此前误记 34」）一视同仁：事实能独立站的删交代留事实；出处登记进 frontmatter 的 `source`，是否属实由 `verified` 记录，核实不了的进账本。出处名在正文只留真对照（下条）；书的进度页的来源名不动。

**指书的清理只删，不改名。** 「书里／书中／原书／全书／书未展开」与作者名这类指书交代，处置是删——**不换成「样本」，也不换成素材名或任何代称**（「书名换『样本』」的旧判例不再沿用）。删掉后句子读得通、事实照旧成立的，当场删，接缝做最小修复（「周志华《机器学习》给的理由是硬的」删名后作「理由是硬的」）；删掉后那句话就不成立的——整句的知识就是书讲到没讲到、讲到哪一章这类素材定位——不当场改写也不硬删，进账本待办清单立「定夺」条，并在返回里报给人裁定。

来源名在正文里只有一种留法：**真对照**——两家以上说法不同、并排摆着，摘掉名字读者就分不清哪个说法是哪家的（对照表的行标签、「京东是另一种接法」）。判法是摘名试读：把来源名连同「的口径」「的例子」「（X）」括注一起摘掉，句子照样成立、也没跟别家说法撞上，就是纯挂名，删；摘掉后两种说法混成一团，就是真对照，留。一家独有的说法、没跟别家并排的，也算纯挂名，删——单一来源的限定不留正文，出处登记进 frontmatter。

## 最容易搞错的一类

「⚠️ 还没定」这类句子最容易被当成「作者没写完」而误删，但它记的不是写作的空白，是被写的那个系统真有一处悬而未决——谁主导协调、哪套切法作数、按不按接口数量约束。这些悬念不会因为挪进账本待办就解决，只会从正文里消失，读者看不到这处系统本身还留着口子。

判一句「⚠️ 还没定」的主语，问的是：这句话说的是「这一页缺一节」，还是「这套设计缺一个决定」。前者删，后者原样留在正文里——包括整张记录着多处悬而未决项的表格，一整张、一个字都不动。

判不准就按留处理：**误删比漏删坏**。误删把系统本身的真实空白从正文里抹掉，读者会以为这处已经定了；漏删只是一句改写腔调混进正文，留到下一轮 review 还能再收一遍。

## 记账：全进账本，正文不留

review 的产出一律进库根 `.wiki/review/` 下与页同路径的账本，正文页不留待办、不留过程账：页是给人读知识的，账是给人处理待办、给下一轮 review 复核的。`知识/机器学习/Loss/Loss.md` 的账本就是 `.wiki/review/知识/机器学习/Loss/Loss.md`，没有就新建。三节，顺序固定：

```markdown
# review 账 · 知识/机器学习/Loss/Loss.md

## 待办清单

1. 补一节：C4 与 ArchiMate 怎么配（文末原标「还缺一节讲…」）
2. 重拟标题：「四、原「专有名词」一节里另外两条」主语是上一稿，往被写的系统上改

## 删句账

- 2026-09-29 · 串联语 · 「本页说的正是那条路走不通之后的另一条」
  原在：开头第二段首句后半。主语是这一页在讲什么，删后逗号改句号收尾

## 判过留的

- 2026-09-29 · 「这是本页为了导航做的组织，文献里没有这种标准分类」
  带「本页」但说的是分类法没有文献依据，主语是事
```

**待办清单**只收欠人的动作，有动作可做、做完可销的才进：补一节、改写一句、重拟标题、统一译名、重排编号、定夺一处取舍。每条以编号起头、动作起句（补 / 改写 / 重拟 / 统一 / 重排 / 定夺…），引原句作语境；换行缩进三格对齐条目文字。不加粗、不设小节、不记轮次——待办是活清单，人处理完删条目，清空就删节。新条目接着现有编号往下排。**已删掉的句子不是待办**：删是 review 当轮做完的动作，它的去处是删句账。

**删句账**每条记：标签（串联语 / 写作指令 / 取证账……按内容起名）、原句加引号、`原在` 指到节与位置、判词一句。**判过留的**收判给「留」但下轮容易被再挑出来的（出处限制、带「本页」字样而主语其实是事的），记原句与为什么是事——防同一句被每轮 review 重判。这两节每轮追加、日期打头，已有条目不覆盖、不重排。**开工先读账本**：「判过留的」里已有的，直接跳过不重判。

## 标题里的非知识内容：记进账本待办，不自己改

判据对标题一样成立——`### 四、原「专有名词」一节里另外两条` 的主语是这一页的上一稿，不是被写的那个系统。但**你不改写句子，而换掉一个标题必然要重拟标题内容**，那是写的人的事。

所以遇到这种：正文照旧不动，把它记进账本的待办清单，类型标成「标题待重拟」，并写清现在这个标题的主语是什么、该往哪个方向改。

不要因为「改不了」就当没看见——实跑里出现过一次，`wiki-write-humanize` 只管断言句、不管主语，`wiki-write-review` 判了「留」就没记账，那个标题两边都够不着，一路留到了成页里。

## 不做的事

- 不改写留下来的句子——遣词造句是 humanize 的活，这一步只搬东西，不改文字。
- 不补内容——「还缺一节讲…」这类句子照原句搬进账本待办清单，不去写那一节。
- 不跑验收命令——`wiki check` 与 `wiki page anchor` 由 `wiki-write` 编排层跑，本步骤不运行 shell，也不联网。
- 不碰指定页之外的任何正文；写的文件只有两个——指定页，和它对应的 `.wiki/review/` 账本。
- 不在正文里立 `## 待办清单`；正文里已有的旧节，原样搬进账本待办清单（接着编号），再从正文删掉。
