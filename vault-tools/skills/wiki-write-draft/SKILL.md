# wiki-write-draft

按调研笔记与 raw/ 素材写一篇 wiki 沉淀页。

## 规则在别处

分区判据与落点在 `wiki` 技能主文件；术语标注、写作判据在 `wiki-write` 技能的 [writing.md](../wiki-write/writing.md)；frontmatter 在 [metadata.md](../wiki-write/metadata.md)。页骨架、区专属规则与验收在落点区门面 `<区>/<区>.md`。**这些规则只定义在那里**，本技能不重复。这份技能只管落笔这一步该怎么走。

## 四步

1. 定落点：决定页放哪个区、挂在哪条路径下。`学习/` 与 `知识/` 之间那一刀，切的是要不要先钉一份基线才敢写，判据见 `wiki` 技能「六区」与「定落点」。
2. 判主题类型：读落点区门面 `<区>/<区>.md`，从它列的骨架里选一副。**判不出来就停下来问人**，不要硬套一副骨架上去。
3. 建页：`wiki page new <路径> <标题>`，**绝不手写 frontmatter**。
4. 按骨架填：一节一节写，写完一节回头看它是不是只讲了一件事，混了两件事就拆开。

## 断网意味着什么

手上能用的材料只有两样：`.wiki/tmp/<slug>/00-调研笔记.md`，和它点名过的 `raw/` 素材。这一步没有 WebSearch，也没有 WebFetch，查不到就是查不到，不能现场去网上补一手。

调研笔记固定三节：`## 源清单` 列抓回来的素材，`## 每份的关键发现` 是逐份的一手记录，`## 矛盾与缺口` 标出几份材料打架、或者压根没查到的地方。写正文时照这个态度处理，凡是落进 `## 矛盾与缺口` 的东西，要么如实写一句「这一条查不到」，要么把矛盾原样摆出来让读者自己判断，**不要凭印象补一个看起来更圆的说法**。编出来的断言和真的长得一模一样，事后没人能凭肉眼分辨出哪句是编的。

页里但凡出现反引号包住的外部代码标识符，心里要有数：`wiki page anchor <页>` 会把驼峰类名、全大写枚举、snake_case、含 `/` 的路径这四种形状挑出来，逐个拿到 `.wiki/anchors.conf` 钉死的基线 commit 里 `git grep`，查不到就判定为编造。断网这一步生不出新的确定性，写得出的只有调研笔记里已经查到的东西。

## 写完自查

跑 `wiki check`，非零退出说明还有问题。`description` 在建页那一刻是空的，机器编不出一句诚实的摘要，那条豁免只对建页成立；写完正文之后要回去把这一句真摘要补上，不要留空转手扔给下一步。
