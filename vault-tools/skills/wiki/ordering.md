# 排序

给一层子页定顺序时读。

## 线还是并列

有的子页是有方向的导览序（专题骨架、步骤链、按依赖序的拆解），有的是并列类目。

**判据：读懂后一页要先读前一页，就是线。** 看后一页是否用到前一页的内容，不看有没有互链。拿不准按并列写，序写错比缺序代价大。

| 形状 | 例 |
|---|---|
| 线 | 电商：增长引擎的产品主线把商品适配当输入，删掉商品适配就读不完整 |
| 类目并列 | Palantir Ontology 的三种 element |
| 环 | 增长引擎三主线；运营指标四段沿环排 |
| 分支 | 机器学习：范式、协议两家加 Supervised Learning 有序，之后两条路任选（互链但各自读得完整） |
| 层间有序、层内并列 | Agent工程 L0–L4 |

是线就在 index 导览文里把序说清。

## 顺序怎么表达

文件名不带序号，文件名与 `title` 两处都只写概念名；正文不写一级标题（阅读器标题栏显示页名）。五区内每一层的先后由这一层的 `.folder.json` 定：`children.<名>.order` 小的在前。

```json
// 知识/机器学习/.folder.json（JSON 不能写注释，这一行只是标注文件名）
{
  "index": "机器学习",
  "children": {
    "训练范式": {"type": "file", "ext": "md", "order": 1},
    "训练协议": {"type": "file", "ext": "md", "order": 2},
    "深度学习": {"type": "folder", "ext": "folder", "order": 3}
  }
}
```

- 沉淀五区每个文件夹（含区根）都有 `.folder.json`，**所有字段都必填**，不许有别的字段：
  - `index`：文件夹自己的页名（不带 `.md`），默认是文件夹名；这一页不列进 `children`。
  - `children`：列全这个文件夹里的每个文件与子文件夹（`.` 开头的不列）。键是名字（文件去掉最后一个扩展名）；`type` 写 `file` / `folder`；`ext` 写扩展名（不带点，无扩展名写 `""`），子文件夹写 `"folder"`；`order` 是这一层不重复的正整数，不要求连续。
- 不用手写：`wiki page new` / `page move` / `page grow` / `page shrink` 跑完会同步，新出现的条目 `order` 接在这一层最大值后面。绕开命令改了目录（编辑器外建页、直接写文件），`wiki check` 会报「文件夹配置：」，照它的修法手改，或用 page 命令重做那次改动。
- `wiki check`：漏列、多列、缺字段、不认识的字段、type / ext 不对、order 重复或不是正整数、去掉扩展名后同名、`.folder.json` 写坏了、`index` 指向不存在的文件都是错误。check 只报不改，照报错改。
- 手改是普通 JSON：键和字符串用双引号，条目之间要逗号、最后一条后面不要逗号。
- 有 `.folder.json` 也要写导览文，它只管先后，为什么这么排要 index 说清：用 `[[X]]` 点名子页，不写「这三页」。

**操作：**

- 线上的新页按阅读序创建，命令会把它接在最后。中途插页改 `order`：要插的位置后面的条目依次加一（或原本就留了间隔，直接用中间的数），再改通导览文的接缝。
- 整层重排只调 `order` 和导览文，不动文件名。
- 挪位置用 `wiki page move`，它会同步父层 `.folder.json`：同层改名 order 不变，换到别的文件夹接在那一层最后。文件夹的页不能单独挪：改名就 move 整个文件夹，换页就改 `index`。

**五区之间的顺序**在 `.wiki/wiki.json` 的 `parts.<区>.order`（`{"version": …, "parts": {"经历": {"order": 1}, …}}`，五区都要有，字段同样必填）。`wiki page move` 会改写它的键，`wiki check` 查断键（按 git 改名记录提示新路径）。
